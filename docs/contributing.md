# Contributing to MetaOpenCoach: Expanding the SAG Ecosystem

Welcome! MetaOpenCoach is more than just a software tool—it's a movement toward **Technological Sovereignty**. The expansion of the boundaries of what a **Sovereign Application Generator (SAG)** can achieve is a collaborative effort.

## The Viral Philosophy: A Community of Forks
The MetaOpenCoach orchestrator is designed as a polymorphic engine. While the core repository focuses on coaching, the real power lies in its **Infinite Versatility**. 

**Forking this project is strongly encouraged.** 

Whether building a "Legal Advisor SAG," a "Medical Protocol SAG," or a completely new category of software, experimental forks are the engine of this revolution. The goal is to create a viral ecosystem of sovereign, local-first applications where the user—not the cloud—is the owner of the intelligence.

---

## How to Contribute

### 1. Fork & Experiment
The best way to contribute is to push the architecture to its limits:
- Create a fork.
- Modify the `template_core`.
- Design new **Hierarchical Metaprompts**.
- Share your results with the world!

### 2. Standard Pull Requests
Improvements for the core engine (security enhancements, build optimizations, or UI polish) are welcome via Pull Requests:
1. **Fork the Repo**
2. **Setup Local Environment** (Python 3.11+ and Node.js 18+)
3. **Draft your changes** (Follow PEP8 for Python and AirBnB style for JS)
4. **Submit a PR** for review.

---

## Coding Conventions

### Javascript (Core Template)
- **Standard**: AirBnB Style Guide.
- **Rules**: Keep it local-first. No external CDNs.
- **Naming**: camelCase for variables, PascalCase for components.

### Python (The Facilitator)
- **Standard**: PEP8.
- **Typing**: Use Type Hints for better maintainability.
- **Orchestration**: All logic must remain AI-agnostic and support local LLM providers.

## Code of Conduct
Please be respectful and professional. A future of digital freedom is being built together.
